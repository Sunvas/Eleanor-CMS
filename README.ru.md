# Eleanor CMS

[English version](README.md)

## Основные принципы

* **Лицензия MIT/X11.** Система не требует размещения копирайтов, реферальных ссылок или иных обязательных атрибутов, подтверждающих использование CMS.
* **Нулевая зависимость от стороннего PHP-кода.** Eleanor CMS не использует сторонние PHP-библиотеки или фреймворки.
* **Фронтенд не требует сборки.** Встроенные JavaScript- и CSS-файлы не требуют компиляции через `npm` или другие инструменты сборки. Для внесения изменений достаточно обычного текстового редактора.
* **Документированный исходный код.** Структура проекта, каталоги, файлы и основные элементы кода снабжены пояснениями, которые описывают их назначение и упрощают изучение системы.

## Пользователи и безопасность

* **Одновременная работа с несколькими пользователями.** На одном устройстве можно одновременно открыть несколько учётных записей в отдельных вкладках браузера. Один пользователь также может быть авторизован на нескольких устройствах.
* **Двухфакторная аутентификация и восстановление доступа.** Для усиления защиты учётной записи можно включить двухфакторную аутентификацию на базе TOTP из приложения-аутентификатора. В случае утраты пароля доступ можно восстановить с помощью одноразовых резервных кодов. При включённой двухфакторной аутентификации доступ можно подтвердить любыми двумя из трёх факторов: паролем, TOTP или резервным кодом.
* **Модульная архитектура и групповая система прав доступа.** Функциональность системы разделена на юниты. Права пользователей определяются их принадлежностью к группам и ролями, назначенными этим группам; один пользователь может входить в несколько групп.
* **Минимальное использование cookie.** Для авторизации используется одна cookie. В сочетании с явной опцией «Запомнить меня» она относится к [аутентификационным cookie, которые не требуют отдельного согласия пользователя](https://europa.eu/youreurope/business/dealing-with-customers/data-protection/online-privacy/index_en.htm#main-article), поэтому для этой механики не требуется отдельный cookie-баннер.
* **Защита от XSS через CSP.** Выполнение inline-скриптов запрещено политикой [Content Security Policy](https://developer.mozilla.org/ru/docs/Web/HTTP/Guides/CSP), что делает классические [XSS-атаки](https://ru.wikipedia.org/wiki/Межсайтовый_скриптинг) на основе внедрённого JavaScript невозможными при действующей политике.

## Архитектура и инструменты

* **Асинхронные события.** Действия, не требующие немедленного выполнения, могут обрабатываться отдельно от основного запроса — например, отправка уведомления не блокирует загрузку страницы.
* **[ЧПУ](https://ru.wikipedia.org/wiki/Человекопонятный_URL) по классическому принципу каталогов и файлов.** URL-структура строится без централизованного роутера: адреса напрямую отражают организацию разделов и ресурсов системы.
* **Расширяемость без глубокой интеграции.** Минимальный юнит может состоять всего из одного файла и не требует регистрации в конфигурации системы. Классы, интерфейсы, трейты и перечисления автоматически загружаются при размещении в соответствующих каталогах.
* **Поддержка командной строки.** Eleanor CMS предоставляет общий CLI-интерфейс, через который юниты могут добавлять собственные команды. Систему можно устанавливать как из браузера, так и из CLI; CLI-установщик поддерживает проверку конфигурации и режим dry-run. Документация установщика доступна на русском и английском языках.
